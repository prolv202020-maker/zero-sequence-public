# 《第零序列》整卷发布流程

**唯一正式线上分支：`main`。** GitHub Pages 只应从 `main` 发布，不能从写作分支部署。

## 顺序

1. **作者私人资料库撰稿**：未定稿正文、作者隐藏设定、未来剧情大纲仅留在 PRIVATE 作者仓库；不要推入公开网站仓库的任何分支。
2. **完成整卷**：每卷十章，逐章3000—3500汉字，核对时间线、人物、能力代价、伏笔和剧情连续性；全部定稿才进入网站暂存。
3. **单独创建网站发布分支**：从最新 `main` 创建 `release/volume-XX`。同一个分支同时提交全部十章、卷目录、上一卷衔接、第三篇目录、首页更新、阅读进度、搜索、sitemap、缓存配置和回归测试。
4. **开 Pull Request 到 `main`**：先保持 Draft；只有所有文件准备完整后才转为 Ready for review。不要将任何章节先单独直接推到 `main`。
5. **必须通过检查**：GitHub Actions `Public publication boundary / audit` 绿色通过，包含作者资料隔离、链接资源、首次访问脚本和阅读流程/独立解锁。失败则在该分支修复，绝不把失败提交合并到 `main`。
6. **一次性合并**：检查通过且人工确认章节清单/防剧透/手机阅读/阅读进度以后，使用 **Squash and merge** 将完整整卷作为一次提交合并到 `main`。
7. **合并后检查**：等待 `main` 的 `audit` 再次绿色通过，核验 GitHub Pages 实际可访问；失败则修复并走新的 PR。不要以为 PR 绿色等于线上部署成功。

## 全卷目录统一标准（以后新增卷也适用）

**第1卷的“本卷章节目录”是全站唯一参考样式。** 新增第31卷及后续卷时，不另写另一套章节目录组件。

- 卷目录必须使用 `main.page`、`p.eyebrow`、`h1`、`p.lead`、`div.list`，其中按顺序列出该卷十章的真实 `../chapters/volume-XX/chapter-001.html` 至 `chapter-010.html` 链接；第1卷额外保留序章。
- 必须加载与其他卷一致的 `assets/css/volume-page.css`、`assets/js/volume-page.js` 和 `assets/js/progressive-archive.js`，并使用当次已确认的最新资源版本号，避免旧脚本缓存。
- 卷目录由统一脚本显示独立的英文全书章号、中文章节标题、右侧“已读／未读／继续阅读”状态、阅读进度及卷间导航；**不要**自行新增另一套手写目录状态或封面英雄区。
- 每卷的章名应提供简洁原始标题，不要把“全书第XXX章”“正式正文”等编辑说明当成章节名；历史卷的冗余后缀可由共享组件清理。
- **阅读状态只读取现有 `zs:part-progress:v1`、`zs:reader:last:v1`，不可重置、迁移或用目录浏览行为写入阅读进度。** 图鉴与任务资料继续按各篇阅读进度独立防剧透。
- 所有新卷通过 `node scripts/test-unified-volume-catalogs.mjs` 的**动态卷数检查**，再进行完整发布回归。新增卷也要同步扩展阅读器的全书章节上限和卷目录上下限。
- 发表前用手机与电脑核对首卷、新卷和跨篇边界卷的目录显示，确认不出现重复章节标题、额外旧模板、错乱已读状态。

## 发布完整性清单

- [ ] 全十章正文已定稿，单章3000—3500汉字
- [ ] 章名、全书章号、上一章/下一章、跨卷边界正确
- [ ] 新卷目录、第三篇目录、首页数量及最新章链接一致
- [ ] 不改变本地阅读进度的现有键名，不重置以前章节
- [ ] 防剧透图鉴只解锁已经正式公开的内容
- [ ] 读者脚本、BGM、手机布局、无障碍导航正确
- [ ] 搜索、sitemap、缓存与静态资源路径完整
- [ ] PR 的全部 checks 绿色
- [ ] 合并到 main 后最终检查绿色、线上阅读链接可访问

## GitHub 仓库设置（需要仓库管理员执行）

在 **Settings → Rules → Rulesets → New branch ruleset** 中，以 `main` 为目标，要求 Pull Request 后才可合并，并要求 status check `audit` 通过（检查所属 workflow 为 `Public publication boundary`）。启用禁止绕过规则的相应选项，避免直接推送到 `main`。在 **Settings → Pages** 中确认仅从 `main`（或以 main 为来源的部署工作流）发布。

> 仓库管理员的 GitHub Ruleset/Pages 权限不能由本发布文档代替。仓库设置未确认以前，本规范是约定而非技术强制。
